# sims-portfolio

Прототип механики сайта-портфолио для двух людей в духе The Sims: лоу-поли комната в эстетике PS1, два персонажа, ходьба по клеткам, радиальное меню, действие с компьютером. Арт заглушечный — важно, чтобы работало и ощущалось как игра.

## Как общаться

Владелец — дизайнер без опыта разработки. Объясняй простыми словами, без жаргона. После каждого этапа сам проверяй в браузере, показывай скриншоты, делай коммит и останавливайся.

## Копирайтинг

- Все тексты на сайте пишутся с маленькой буквы: кнопки, заголовки панелей, подписи, черты, уведомления, имена («соня сурм», «паша архангельский»). Исключение — аббревиатуры, они пишутся большими (PS1, ПИН, ИИ).
- Без висячих предлогов: короткое слово (предлог, союз, частица — «в», «к», «с», «и», «а», «на», «по», «не» и т. п.) не остаётся в конце строки, его склеивают со следующим словом неразрывным пробелом. Делать это автоматически при выводе текста, чтобы в `data.js` можно было писать обычные пробелы.
- Правило касается и новых текстов, которые предлагаешь сам.

## Работа вдвоём

Над проектом работают два человека, у каждого свой Claude. `main` — это живой сайт: всё, что туда попало, через минуту публикуется.

- В `main` напрямую не пушить. Одна задача — одна ветка с понятным названием (`radio-volume`, `stage-12-wardrobe`). Ветку создаёшь сам в начале работы.
- Перед началом: `git pull` в `main`, потом ветка от свежего `main`.
- Когда задача готова и проверена в браузере — открыть pull request: два-три предложения, что изменилось, и скриншот. Влить может любой из двоих.
- Превью: на каждый пуш в ветку Vercel (проект `sims-portfolio` в аккаунте владельца) собирает отдельную копию сайта и пишет ссылку в pull request. Ссылки открываются без входа. Если сборка ветки упала, это видно в pull request до слияния — такую ветку не вливать. Живой сайт по-прежнему на GitHub Pages, Vercel его не трогает.
- Большие правки (новый этап, смена моделей, чужие тексты в `data.js`) сначала смотрит второй человек.
- Не работать одновременно над одним файлом, особенно `style.css`, `main.js`, `data.js`. Берёшь задачу — пометь в `PLAN.md` строкой «в работе: имя».
- `CLAUDE.md` и `PLAN.md` обновлять в той же ветке, что и код.

## Стек

- Vite + обычный JavaScript + Three.js. Без React и игровых движков.
- Весь контент (персонажи, мебель, действия, тексты, настройки PS1) — только в `src/data.js`. Ничего из этого не зашивать в код.
- Запуск: `npm run dev`. Для проверки в приложении — конфигурация `sims-portfolio` в `.claude/launch.json` (порт 5183).

## Договорённости о сетке

- Клетка — `[столбец, ряд]`. `[0, 0]` — дальний угол, где сходятся стены. Столбцы растут вдоль задней стены (ось X), ряды — к зрителю (ось Z). Одна клетка = 1 единица.
- Стены: `north` (вдоль ряда 0) и `west` (вдоль столбца 0). Передние срезаны.
- Направления: `north` = −Z, `south` = +Z, `west` = −X, `east` = +X.
- Стул не блокирует проход: персонаж встаёт на его клетку и садится.

## Модели персонажей

Kenney Mini Characters (CC0, kenney.nl/assets/mini-characters). Скачаны с копии на GitHub (`ivanlarios22/Zapopan`, совпадает побайтно с `Jolomolokolo/Trackenomics`). Лежат в `public/models/people/`: 12 файлов `character-{female|male}-{a…f}.glb` + общая текстура-палитра `Textures/colormap.png` (на неё ссылаются все glb). Модель выбирается полем `model` у персонажа в `data.js`, цвет `color` — только акцент интерфейса (модели не перекрашиваем).

- `character-female-a.glb` изменён: у неё в руках были костыли (8 отдельных кусков геометрии на костях рук, по 32/36/40/56 вершин). Их треугольники схлопнуты в точку скриптом `tools/remove-hand-props.mjs` (файл того же размера, остальное не тронуто; после правки руки заканчиваются на x = 0.38, как у male-a). Оригинал — в истории git.
- Скелет: `root`, `torso`, `leg-left/right`, `arm-left/right`, `head`. Модель смотрит на +Z. Рост 0.776 ед. модели, масштаб `SCALE` = 1.5 / 0.776.
- Анимации (32): static, idle, walk, sprint, jump, fall, crouch, sit, drive, die, pick-up, emote-yes, emote-no, holding-*, attack-*, interact-right/left, wheelchair-*.
- Нет «помахать» и «встать». Взмах — кодом (`Character.wave()`: поворот `arm-right` вокруг локальной Z поверх анимации; `WAVE.raise` −1.0, `swing` 0.15 — при подъёме дальше ~−1.2 кисть уходит в голову, проверено по вершинам на всех 12 моделях). Вставание — crossfade sit → idle (сделать на этапе 4).
- Поза `sit`: `root` опускается на 0.15 ед. модели, таз оказывается ~0.026 ед. над точкой персонажа, ноги вперёд (~0.14). Чтобы сесть на стул с сиденьем на высоте `h`, персонажа поднимаем на `h − 0.026·SCALE` и сдвигаем назад к спинке. Сиденье стула сейчас 0.49 (верх).
- Скорость шага: `WALK_CYCLE_SPEED` = 0.915 ед. модели/с (амплитуда стопы 0.305 за полцикла 0.33 с).

## Требования

**Комната.** 6×5 клеток (с этапа 13: при людях нормальных пропорций 8×7 выглядела залом; на этапе 7 было 8×7, до него 6×6), видны две дальние стены. Камера фиксированная, изометрическая, ортографическая (угол — как в `reference/02-camera-grid.webp`). Мебель из примитивов в коде: стол с компьютером и стулом, диван, книжная полка, торшер, окно, ковёр. Текстуры процедурные 32×32, фильтрация nearest.

**PS1.** Рендер ~480 px по высоте, дрожание вершин слабое — `vertexSnap: 960` ступенек на высоту экрана (пробовали 160, 240 и 0 — выключено); до этапа 16 рендер был 320 — люди нормальных пропорций выходили слишком грубыми с растягиванием без сглаживания. Дрожание вершин — добавлять в стандартные материалы (через `onBeforeCompile`), не заменять их своими, иначе сломается скелетная анимация. Уменьшение палитры + дизеринг финальным проходом. Плоское освещение, лёгкий туман. Кнопка «PS1 вкл/выкл» в углу. Аффинное искажение текстур НЕ делаем (камера ортографическая — эффекта не видно). Едва заметное покачивание камеры, чтобы дрожание читалось (выключатель в `data.js`).

**Персонажи.** Два лоу-поли человека (разные модели Kenney), имена и данные из `data.js`. Переходы анимаций через crossfade.

**Ходьба.** A* по клеткам без библиотек, в обход мебели. Поворот по направлению, Walking в пути, Idle на месте. Клик по полу — идёт выбранный. Новый клик на ходу перестраивает маршрут без рывка. Клик по занятой клетке — идти к ближайшей свободной. Столкновения персонажей не учитываем.

**Отладка.** Клавиша G: сетка клеток, занятые — красным, текущий маршрут.

**Интерфейс** (HTML поверх 3D; по мотивам `reference/`, но без логотипов и фирменных элементов Симс, никакого зелёного кристалла):
- Слева колонка портретов, выбранный подсвечен (`reference/03-portraits-panel.png`). Клик по портрету выбирает; клик по второму персонажу в сцене — меню взаимодействий, в нём пункт «выбрать».
- Под выбранным — светящееся кольцо.
- Наведение на интерактивный объект/персонажа — светлая обводка по силуэту (запасной вариант — подсветка яркостью).
- Радиальное меню у курсора: «таблетки» по кругу с точками-соединителями, в центре портрет выбранного (`reference/01-radial-menu.png`). Короткая анимация появления, клик мимо закрывает, у края экрана не вылезает за границы.
- Нижняя панель (с этапа 9, по мотивам нижней панели The Sims 2): четыре блока сложной формы — портрет с именем, текущим действием, значками интересов и часами; потребности; работа; «пара слов» (текст от лица персонажа).
- Клики по интерфейсу не проваливаются в сцену. Десктоп с мышью и (с этапа 9) телефон — см. «Телефон» ниже.

**Взаимодействия.**
- Компьютер: «показать работы» («ссылки» убраны по просьбе владельца; панель `links` в коде осталась). Персонаж идёт к стулу → поворачивается к столу → Sitting → через секунду панель с данными выбранного → закрытие → Standing → Idle.
- Действие — цепочка шагов, описанная в `data.js`. Отмена (крестик или клик по полу) работает на любом шаге, включая дорогу.
- Стул занят — пункт меню неактивен с подписью «Занято».
- Клик по выбранному персонажу: «помахать» («о себе» убрано по просьбе владельца, и у второго персонажа тоже; панель `about` в коде осталась). Клик по второму — взаимодействия (этап 10, см. ниже).
- Остальная мебель не интерактивна, но добавляется так же через `actions` в `data.js`.

## Как устроен код

- `src/main.js` — сцена, камера (вписывается в экран с отступами под интерфейс: `SCREEN_MARGINS`), свет, цикл отрисовки, кнопки. `toScreen()` переводит точку мира в CSS-пиксели с учётом PS1-растяжения; для кликов мышью нужен обратный перевод через тот же `view`.
- `src/room.js` — пол, стены, мебель по `type` из `data.js` (`builders`). У каждого предмета `userData.furnitureId` и `userData.interactive`.
- `src/ps1.js` — `applyPS1(object)` включает дрожание вершин во всех материалах объекта (вызывать и для роботов); `PS1Pass` — рендер в низком разрешении + палитра + дизеринг.
- `src/grid.js` — занятые клетки и отладочный слой (`setPath(points)` для маршрута).
- `src/textures.js` — процедурные текстуры.
- `src/characters.js` — `loadModel(name)` (с кэшем, текстура nearest) и класс `Character`: копия модели через `SkeletonUtils.clone`, материалы → Lambert с той же текстурой, `play(key)` с crossfade (`'wave'` → `wave()`), `wave()` возвращает Promise, `walkTo(c, r)`, `update(dt)`.
- `src/pathfinding.js` — A* в 8 направлениях без срезания углов, `nearestFreeCell`.
- Клики: `pick(x, y)` в `main.js` → `{ type: 'character' | 'object' | 'floor', … }` с учётом PS1-растяжения (`view`). Клик по выбранному персонажу — радиальное меню `characterActions`, по второму — `social.actions` (взаимодействия, «выбрать»); по интерактивному предмету — меню его `actions`; по полу — отменить задачу (персонаж встанет) и идти.
- Действия: `src/actions.js` → `performAction()` собирает цепочку шагов из полей действия в `data.js` и запускает её через `Character.runTask(activity, steps)`. Шаги ждут через `task.step(promise)` — при отмене сразу выходят с `Cancelled`; «уборка» (`task.onCleanup`) выполняется в обратном порядке: закрыть панель → встать → остановиться → освободить место. `occupancy` (Map в `main.js`): ключ `sitOn` или id предмета → персонаж; занятое место в меню — `disabled` + «Занято».
- Ожидания у персонажа: `until(pred)`, `wait(sec)`, `walkToAsync`, `faceTo(yaw)`, `tweenTo`, `sitDown(seat)` (подходит к `seat.approach`, затем опускается на сиденье), `standUp()` (обратно в `standSpot`). Точка посадки — `seatPoint(item)` в `room.js` по таблице `SEATS` (стул: подход сзади, диван: спереди). Тень и кольцо выбора держатся на полу, когда персонаж поднят.
- Меню — `src/menu.js` (`open({x, y, portrait, accent, items, onPick})`, сам не вылезает за края). На телефоне (до 640 px) круг сжат в овал (`COMPACT`: 46 × 78 px) и кнопки мельче (класс `compact`) — меню из шести пунктов занимает ~313 px; если меню всё равно шире или выше экрана, оно уменьшается целиком (`scale`). Панели — `src/panels.js` (`open(kind, characterData)` → `{ closed, close }`); панель одна на экране, новая закрывает предыдущую (её `closed` выполняется с `'replaced'`) — тот, кто открыл предыдущую, продолжает сидеть/держать предмет, пока его не отменят. Панель стоит слева у портретов, чтобы компьютер был виден. Панель `shelf` общая (`panels.shelf.shared`, ссылки в `panels.shelf.links`), без имени в заголовке.
- Комната «домик щелочи» (этап 7): типы `designDesk`, `macbook` (`screen: 'design' | 'code'`), `designChair` (сиденье как у `chair`, есть в `SEATS`), `bookcase`, `wardrobe`, `plant`, `panoramicWindow`, `poster`. Старые типы (`desk`, `computer`, `chair`, `bookshelf`, `window`) оставлены в `builders`. Предметы на стене (`wall`) получают ширину по числу своих клеток вдоль стены. Вид из окна (`tex.cityView(cells)`, 32 px на клетку × 72) и плакат (`tex.poster(item)`, 72×96, текст через canvas с порогом альфы) — исключения из правила 32×32.
- У стен, стекла окна и бумаги плаката `userData.noSnap = true`: иначе плоскость стены при прыжке вершин перекрывает то, что на ней висит. Проверено магентовой заливкой стекла и плаката при 300 положениях камеры — промахи только там, где перед окном стоят стол и рама.
- Листья растений тоже `noSnap` (`steady()` в `room.js`): тонкие листья при дрожании протыкали друг друга и мерцали. Материал `leaf` только для листьев и стеблей (тёмно-зелёный убран по просьбе владельца — выглядел чёрным) — дрожание включается на материал.
- Этап 8. Места действия: `goTo` или `spots` (несколько клеток, ключ занятости `sitOn@c,r`); `freeSpot()` в `actions.js` выбирает место внутри задачи (после отмены прежней), меню берёт его же для «занято». После анимации — `prop` (`Character.takeProp('book' | 'laptop')` / `putAway()`), `thenFace` (`'viewer'`), без панели сидящий/держащий ждёт отмены. Книга: `reach` (interact-right, один раз) → `hold` (holding-both), книга следует за кистями (`handPoint`: 0.26 ед. модели по оси X кости руки). Ноутбук: руки за спину → дугой на колени (`LAPTOP.lap`, z 0.4 — короче руки не дотягиваются) → крышка → печать (`ARMS.type`, подобрано перебором). `propGen` обрывает доставание при отмене.
- Руки поверх анимации (взмах, `arms`): микшер three.js переписывает кость, только когда её поза меняется, — в неподвижных позах (sit, holding-both) докрутка копилась. Поэтому в начале `update()` кости рук возвращаются к сохранённой позе из анимации (`armBase`).
- Крупный план (`closeUp` у предмета на стене): `makeShot(center, quat, corners, margins)` в `main.js` — кадр камеры, между кадрами плавный переход (`cam`, `CLOSEUP_TIME`). Класс `closeup` на `body` прячет интерфейс; персонажи скрыты, пока камера у стены. Картинка плаката — `tex.imagePoster(url)` 240×300 с mipmaps; под рамкой тёмная подложка без дрожания (иначе в щели видны обои).
- Макбук шириной 0.51; экраны `tex.screen(60, 25)` и `tex.designScreen(60, 25)` под его пропорции.
- Ковёр пропадал из-за дрожания вершин, а не точности глубины (буфер 24-битный): пол — два огромных треугольника, при прыжке углов по сетке его плоскость «наклоняется» и перекрывает ковёр. Поэтому у пола и ковра `userData.noSnap = true` (их пропускает `applyPS1`). Проверка: рендер при 300 положениях камеры и чтение пикселей ковра — 0 промахов. Слои: ковёр 0.02, тень 0.035, кольцо 0.05; камера near/far = 4/40.
- Дрожание у персонажей отдельной силой: `ps1.characterSnap` в `data.js` (0 — выкл, по умолчанию; 2 — вдвое слабее; 1 — как у комнаты). При 1 мелкие детали лица (глаза, очки) прыгают сквозь лицо и выглядят рваными. Сила — uniform `uSnapScale` на материал (`material.userData.snapScale`); силуэт обводки берёт силу обводимого объекта (`pass.render(..., outlineSnap)`).
- Проверено на этапе 4: полное действие, «Ссылки», отмена по дороге (клик по полу), отмена сидя (крестик), смена персонажа, пока первый сидит, «Занято» у второго, взмах, «О себе», меню у краёв экрана, раскомментированный пример с диваном.
- Кадр всегда идёт через `PS1Pass` (`ps1.js`), в том числе без PS1 (тогда масштаб 1, без палитры, MSAA 4). Обводка: наведённый объект переносится в слой `OUTLINE_LAYER` (`setOutlined`), рисуется белым силуэтом в `pass.mask`, финальный шейдер рисует светлый контур по краю силуэта. Мешам, которые не нужно обводить и ловить кликом (тень, кольцо), ставим `userData.noOutline` и пустой `raycast`.
- Сгенерированная мебель (этап 13): поле `model` у предмета в `data.js` (путь от `public/models/`, например `furniture/sofa.glb`). `room.js` сначала ставит заглушку из `builders`, потом `loadFurnitureModel` заменяет её детали моделью (материал → Lambert с той же текстурой, nearest, `applyPS1`); группа, место, поворот и `furnitureId` не меняются. Модель уже подогнана под клетки: её делает `tools/blender/furniture.py` (настройки предмета — `ASSETS` в начале файла: рамка в клетках, масштаб, бюджет треугольников, размер текстуры). Запуск: `/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P tools/blender/furniture.py -- sofa`. Исходники генерации — `models-src/<имя>/` (только локально, см. `models-src/README.md`). Перед у предмета — +Z, как у `builders`; высота сиденья должна совпадать с `SEATS` (масштаб дивана 1.625 подобран под 0.46).
- Свои персонажи (этапы 16–17): `tools/blender/character.py -- <имя>` собирает `public/models/people/<имя>.glb` (тело гнётся по скелету Mixamo, кости без «mixamorig:», движения под ключами сайта: idle, walk, sitDown, sit, standUp, type, wave) и `<имя>.json` (замеры: `walkSpeed`, `sitSeat` — высота попы сидя, `sitHipsY`, `animations` — ключ → повторяется ли). `loadModel` читает json рядом с glb: есть — модель «своя» (`this.rig`), нет — Kenney. У своих: масштаб 1 (`modelScale`), руки кодом не докручиваются (`poseArms`, взмах — пропускаются), взмах — движение `wave`, посадка — `sitDown` → `sit`, вставание — `standUp`, кисти для предметов — кости `RightHandIndex1`/`LeftHandIndex1`, ноутбук ставится под кисти в позе `type` (`LAPTOP_RIG`), чего нет в `animations` — не играется. `sitPose` у действия в `data.js` — движение сидя (за макбуком — `type`). Во взаимодействиях (`social`) — `actorAnimation` / `targetAnimation` (talk, dance; laugh — когда появится); играют, только если движение есть у модели, по окончании — idle. Анимация «на двойках» — `ps1.animationFps` (только у своих моделей). Портрет своей модели снимается по кости `Head`.
- Особняк (этап 14). `room.wainscot` в `data.js` включает стиль особняка: стены из двух частей (снизу панели `tex.wainscot`, выше обои `tex.damask`), поручень, карниз и плинтус (`steady`), пол `tex.herringbone`. Окно — `mansionWindow` (переплёт, шторы `tex.velvet`, ламбрекен; `view: 'night'` — ночной `tex.cityView`), ковёр `pattern: 'persian'` → `tex.persianRug`. Свет — `lighting` в `data.js`: слабый общий + холодный «из окна» (`main.js`), лампы — `light*` у торшера и столика с лампой (`sideLamp`, передний угол [5, 4]) и `lampLight` у стола (`lampLight()` в `room.js`, ореол — спрайт `halo()`, мерцание — `flickerLamps()` в `main.js`, `lighting.flicker`). Без `wainscot` и `lighting` — прежняя светлая студия. Мебель особняка — builders `mansionDesk` (верх 0.79 = `SURFACE_HEIGHT.desk`, на нём макбуки), `mansionChair` (в `SEATS`, как `designChair`), `mansionBookcase` (книги — бруски с текстурой `tex.bookSpines`), `mansionWardrobe`; материалы `mahogany*` (цвет `colors.mahogany`), `leatherTop`, `bookRows`, `greenShade`. Прежние типы остались в `builders`. Модель из glb перекрашивается полем `tint`. Декор: `mansionFloorLamp`, `mansionPlant`, `painting` (картина `tex.oilPainting(seed)`), `sconce` (бра с лампой и ореолом), рама `goldFrame()` — у картины и у плаката с `frame: 'gold'`; `shift` у предмета на стене — сдвиг вдоль стены от центра клеток.
- Запечённый свет (этап 14): в браузере `await __app.exportForBake()` (только dev; `vite.config.js` принимает файлы в `models-src/bake/`), потом `/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P tools/blender/bake.py` (~10 с) → `public/textures/bake/{floor,north,west}.png`. Скрипт прячет пол и стены (по именам `floor`, `wall`), ставит вместо них плоскости с той же развёрткой, что у граней BoxGeometry, лампы — точечные, окно — светящийся прямоугольник, абажуры не дают тени; запекает Diffuse без цвета, значения делятся на `lighting.baked.exposure`. На сайте у пола и двух высоких стен `MeshBasicMaterial` с `lightMap` (`lit` в `buildRoom`; кусок карты по высоте стены — через `offset`/`repeat`), сила = `brightness × exposure × π`. Низкие передние стены, поручни, мебель и персонажи — живой свет. Подвинули мебель или лампы — перезапечь. Плакат с `selfLit` не зависит от света.
- `src/ui.js` — колонка портретов и нижняя панель (`createUI` → `setPortrait`, `setSelected`, `setActivity({icon,label}|null)`). Слой `#ui` с `pointer-events: none`, панели внутри — `auto`, поэтому клики по интерфейсу не попадают в сцену.
- Досье (этап 9): `ui.js` строит три блока `.hud-block` (перемычки между ними — `::before` с `z-index: -1`, у `.hud` `isolation: isolate`). Левый `.hud-me` выше остальных: имя, портрет + действие, интересы (кнопки с подсказкой `withTip`: мышью при наведении, пальцем по нажатию), часы. Дальше по порядку: потребности — содержимое вкладки из `dossier.tabs` (`views.needs`; значки-переключатели показываются, только если вкладок больше одной), работа — `jobs` (`place`, `role`), справа `.hud-note` — `note` персонажа (строка или список абзацев), высотой как блок с портретом (230 px), длинный текст прокручивается. Данные у персонажа: `needs` (ключ → 0…10, подписи и порядок — `dossier.needs`, половина слева, половина справа), `interests` (`icon`, `label`, необязательный `description`), `jobs`, `note`. Цвет шкал: от 60% зелёный, от 30% жёлтый, иначе красный. Высота средних блоков постоянная (180 px) — если работ больше трёх, рамка прокручивается. Шире телефона панель всегда во всю ширину окна (`left`/`right` 8 px): портрет — `flex: none`, остальные растягиваются (`flex-basis` 298 / 360 / 320 — наименьшие ширины, «пара слов» растёт быстрее). Когда и они не влезают (окно уже 1240, 1015 и 845 px), панель уменьшается (`scale` 0.82 / 0.68 / 0.5), а её ширина до уменьшения — `(100vw − 16px) / scale`, чтобы после уменьшения снова была во всю ширину. Черт (`traits`) и шкал характера больше нет; туалета и гигиены в потребностях нет, вкладку «отношения» и столбик настроения владелец попросил убрать.
- Телефон (ширина до 640 px; граница одна и та же в `style.css` и `MOBILE` в `main.js`): `roomShot` вписывает комнату между портретами сверху и нижней панелью (её высота берётся из DOM, поэтому после `createUI` ещё раз вызывается `resize()`), `makeShot(..., zoom)` с `MOBILE_ZOOM` = 1.1 — комната в 1,1 раза шире экрана, края чуть обрезаются (край шкафа и угол стола). Шкаф для одежды теперь на одну клетку ([0, 4], одна дверь — `wardrobe` с `w < 1.5`). Нижняя панель на телефоне: блок портрета на всю ширину (сетка, `.hud-me-row` — `display: contents`, дата скрыта), под ним вкладки `.hud-mtabs` «потребности | работа | пара слов» (создаются в `ui.js`, `data-mtab` на `.hud`). Портреты — в ряд, письмо и панели — на всю ширину. У холста `touch-action: none`, обводка при наведении — только от мыши. Между 640 и 1240 px панель как на десктопе, но уменьшена (`scale`).
- Стиль интерфейса «хром» (по мотивам старых скинов плееров): засвеченный серебристый корпус с розовыми отливами + голубые детали двух тонов. Все цвета — переменные в `:root` в начале `style.css`: `--chrome*` (корпуса панелей, меню, письма, баннера), `--blue-a*` (яркие глянцевые кнопки, шарики-крестики, точки меню), `--blue-b*` (светлые утопленные «экранчики»: часы, шкалы, рамки с текстом, заголовок панели, название песни). Новые элементы красить только через эти переменные. Цвета шкал потребностей (зелёный/жёлтый/красный) и акцент персонажа оставлены. Сверху у `--chrome` — крупный белый засвет (первый слой градиента). Портреты слева — такие же голубые кнопки, выбранный без свечения (белый кант + кольцо цвета персонажа).
- Шрифты. Основной — Inter (`@fontsource/inter`, импорт в начале `main.js`, только 600 и 700, кириллица + латиница), `letter-spacing: -0.06em` на `body` (у кнопок и полей сброс отменён). Заголовки (`.hud-title`, `.hud-name`, `.panel-title`, `.notice-title`, `.hud-tip-title`) — пиксельный 5by7 из папки `fonts/` (жирный, `5by7_b.ttf`; кириллица есть). Пиксель буквы = 0,1 размера шрифта, поэтому только 10 или 20 px, иначе края мылятся; расстояние между буквами родное (0). На буквах заголовков блик: градиент через `background-clip: text` с повтором на каждой строке (`1lh`), тень — `filter: drop-shadow` (обычная `text-shadow` просвечивает сквозь такие буквы). Кнопки — Inter. Вкладки на телефоне («потребности | работа | пара слов») — 5by7 15 px (20 px не влезает; на телефонах с плотностью 2–3 точка 1,5 px всё равно чёткая), ширина вкладки по длине слова.
- `src/typo.js` — `typo(text)` склеивает короткие слова со следующим неразрывным пробелом (и пробел перед тире); `typoDeep` в начале `main.js` прогоняет через неё все данные из `data.js` (кроме `url`, `image`, `model`). Тексты, собранные в коде (заголовок панели «работы — имя»), оборачивать в `typo()` отдельно. Никаких `text-transform: uppercase` в стилях — правило маленькой буквы.
- Взаимодействия (этап 10, пока без движений): `performSocial()` в `actions.js`. Второй персонаж отменяет своё дело и получает свою задачу «ждать»; задачи связаны — отмена любой отменяет вторую (через `task.cancel()` без ожидания, иначе уборки ждут друг друга вечно). Первый идёт в свободную соседнюю клетку (`spotNear`: сначала по сторонам), оба поворачиваются друг к другу, `src/banner.js` показывает баннер сверху по центру (`social.duration` секунд, крестик отменяет). Текст: `{actor}`, `{target.acc}`, `{gift}` → имена из `forms` персонажа (падежи), затем `typo()`. Вложенное меню (`choices`, подарок) — повторный `openMenu` в той же точке. Пока висит баннер, письмо-приветствие спускается ниже (`#ui:has(.banner)`).
- `src/radio.js` — радио (этап 11, `radio` в `data.js`): `createRadio(corner, data)` ставит плеер первым в `#corner`. Звук — из спрятанного iframe soundcloud (1×1 px за краем экрана, не `display: none`), управление через Widget API (`w.soundcloud.com/player/api.js`, грузится сам, когда браузер свободен, чтобы по нажатию песня включалась сразу). Список песен — `getSounds` после `READY`; случайная — `skip(i)`. После `FINISH` по порядку soundcloud сам включает следующую (мы — только после последней), в случайном режиме — `skip` сами. Громкость — в `localStorage` (`radio-volume`). Высота угла с кнопками — CSS-переменная `--corner-bottom` (считает `main.js`): под ней письмо, на телефоне баннер и панели. В `__app.radio` — `widget`, `toggle`, `next`. В скрытой панели браузера музыка играет по-настоящему — после проверок ставить на паузу.

- `src/portraits.js` — `renderPortrait(renderer, gltf)` снимает голову модели в 96×96 (dataURL), в интерфейсе показывается с `image-rendering: pixelated`.
